1. What is Hibernate?
------------------------
Hibernate is a ORM framework, ORM stands for Object Relational mapping which maps java objects to database tables
so we can perform database operations using java objects instead of writing SQL manually.

Advantages:
Reduces JDBC boiler plate code
Supports lazy loading.
Provides automatic table mapping.
Provides transaction management.
Supports HQL and Criteria API.

-----------------------------------
2. Hibernate Architecture
-----------------------------------

Main components:

Configuration
SessionFactory
Session
Transaction
Query

Configuration -> Reads the hibernate configuration

SessionFactory ->
SessionFActory is a heavyweight object used to create Hibernate sessions
usually we create one SessionFactory per database while bootup of the application

Session -> used to interact with the database and perform db operations

Session session = sessionFactory.openSession();

Transaction -> Manages commit/rollback

Query -> Used for HQL/JPQL queries

---------------------------------------
3. What are Hibernate entity states?
---------------------------------------

Transient ->

Object is created but not associated with Hibernate session.
User user = new User();
user.setName("Ravi");

No DB connection yet.

Persistent ->

Object is associated with Hibernate session.
session.save(user);
Now Hibernate tracks changes.

Detached ->
Session is closed, but object still exists in Java memory.
session.close();

Removed ->
Object is marked for deletion.
session.delete(user);


-------------------------------------------
4. What is dirty checking in Hibernate?
-------------------------------------------

Dirty checking means Hibernate tracks the changes of persistent objects and updates the database
during transaction commit

Session session = SessionFactory.openSession();
Transaction transaction = session.beginTransaction();
User user = session.get(User.class, 1L);
user.setName("Ravi Teja");
transaction.commit();

Even without calling update(), Hibernate fires update query because the object is persistent.


----------------------------------------------
5. Difference between get() and load()
----------------------------------------------

get() immediately fetches the object from DB and returns null if not found.
load() returns a proxy and hits the DB only when the object is accessed.

| get()                         | load()                                       |
| ----------------------------- | -------------------------------------------- |
| Hits DB immediately           | Returns proxy first                          |
| Returns null if not found     | Throws ObjectNotFoundException when accessed |
| Use when object may not exist | Use when object definitely exists            |


-------------------------------------------
6. Lazy Loading and Fetching
-------------------------------------------

Lazy loading means related data is loaded only when it is accessed.

User user = session.get(User.class, 1L);
user.getOrders(); // orders loaded here


--------------------------------------------
7. What is eager loading?
--------------------------------------------

Eager loading means associated data is loaded immediately along with the main entity.

@OneToMany(fetch = FetchType.EAGER)
private List<Order> orders;

-------------------------------------
8.Lazy vs Eager loading
-------------------------------------

| Lazy                                  | Eager                              |
| ------------------------------------- | ---------------------------------- |
| Loads data when accessed              | Loads immediately                  |
| Better performance generally          | Can load unnecessary data          |
| May cause LazyInitializationException | Avoids LazyInitializationException |
| Default for collections               | Default for ManyToOne/OneToOne     |


----------------------------------
8. Caching
----------------------------------

first level cache ->  First-level cache is session-level cache. It is enabled by default and cannot be disabled.

User u1 = session.get(User.class, 1L);
User u2 = session.get(User.class, 1L);

Only one sql is fired since the u2 is fetched from thw cache


second-level cache ->

Second-level cache is associated with SessionFactory. It is shared across sessions. It needs explicit configuration

Session 1 → loads User 1
Session 2 → can reuse cached User 1

9. What is HQL?
------------------------------
HQL -> Hibernate Query Language

It is similar to SQL but works with entity names and fields instead of table names and columns.

What is the difference between JPA and Hibernate?
-------------------------------------------------------

JPA is a Java specification that defines standard APIs and rules for ORM. Hibernate is one of the implementations of JPA.

Annotations like @Entity, @Id, @OneToMany come from JPA, while Hibernate provides the underlying ORM implementation.



-----------------------------------------------------------------
mappedBy / owning-side concept
-----------------------------------------------------------------

the owning side is the entity that manages the foreign key

In a Department-Employee relationship, Employee is usually the owning side because it contains department_id using @JoinColumn

Department is the inverse side and uses mappedBy = "department" to indicate that the relationship is already
managed by the department field in Employee.

@Entity
class Employee {

@Id
Long employeeId;

String employeeName;

@JoinColumn("department_id")
@ManyToOne
Department department;

}


@Entity
class Department {

@Id
Integer departmentId;

String departmentName;

@OneToMany(mappedBy = "department", fetch = FetchType.LAZY)
List<Employee> employees;

}


Now suppose we fetch all departments:

List<Department> departments =
        departmentRepository.findAll();

Hibernate first executes
SELECT * FROM department;

that's 1 query

Because employees is LAZY, Hibernate has not yet fetched the employees.


for (Department department : departments) {

    System.out.println(department.getName());

    for (Employee employee : department.getEmployees()) {
        System.out.println(employee.getName());
    }
}

department.getEmployees() -> for each department if executes
select from employee where department_id = ?

so that's 1 + N
1 -> to fetch all N departments
N -> fetch the employees in each department

That's the N+1 problem

this happens because the Fetch type is Lazy

We can solve this using JOIN FETCH

public interface DepartmentRepository
        extends JpaRepository<Department, Long> {

    @Query("""
        SELECT DISTINCT d
        FROM Department d
        LEFT JOIN FETCH d.employees
    """)
    List<Department> findAllWithEmployees();
}

then List<Department> departments =
             departmentRepository.findAllWithEmployees();

this will populate both employees and departments in both the classes
