1) What is the Spring Framework and what are its core modules?

Spring is a comprehensive framework for building Java applications.
Its primary feature is Dependency Injection and IoC, which decouples dependencies.
Core modules include Spring Core (IoC container), Spring AOP, Spring Web/MVC, and Spring Data access.
Spring Boot is a project that simplifies Spring application setup.

2) What is the difference between IoC (Inversion of Control) and Dependency Injection (DI)?

IOC(Inversion of control) : Instead of Application creating objects spring creates them, control passed to spring
Control is "inverted" from developer to framework

DEPENDENCY INJECTION : technique of injecting dependencies into objects
It's a design pattern - specific way to achieve IoC
There are different types of DI:

Constructor Injection
Setter Injection
Field Injection


3) What are the different types of Dependency Injection? Explain each with a code example.

public class Employee {

    // 1. FIELD INJECTION
    @Autowired
    private Department department;

    // 2. SETTER INJECTION
    @Autowired
    public void setDepartment(Department department) {
        this.department = department;
    }

    // 3. CONSTRUCTOR INJECTION
    public Employee(Department department) {
        this.department = department;
    }
}


Best Practice

public class Employee {
    private final Department department;  // immutable

    // Constructor injection - RECOMMENDED
    public Employee(Department department) {
        this.department = department;
    }
}


4) What is a Spring Bean? How does Spring create and manage beans?
A spring bean is a java object instantiated, assembled and managed by Spring IOC container

Stereotype Annotations (Complete List):

@Component - Generic component
@Service - Business logic layer
@Repository - Data access layer
@Controller - Web controller layer
@RestController - REST endpoint

Bean Creation & Registration Process:

Component Scanning - Spring scans classpath for annotated classes
Bean Definition Creation - Creates metadata for each class
Instantiation - Creates bean instances
Dependency Injection - Injects dependencies
Registration - Stores in IoC container (HashMap-like structure)


5) How do you achieve API versioning in Spring Boot?

API versioning means supporting multiple versions of the same API so that existing clients don't break
when you introduce incompatible changes.

there are several ways to achieve this

1. URI/Path versioning — most common
ex :
GET /api/v1/users/10
GET /api/v2/users/10

2. Request parameter versioning
ex:
GET /users/10?version=1
GET /users/10?version=2

3. Header versioning
ex:
GET /users/10
X-API-VERSION: 1


Spring MVC has built-in API-versioning support through the version attribute
@GetMapping(value = "/users/{id}", version = "1")
public UserV1 getUserV1(@PathVariable Long id) {
    // ...
}



------------------------------------------------------------------------------------
self invocation using @Transactional
------------------------------------------------------------------------------------

@Service
public class OrderService {

    public void methodA() {
        System.out.println("A");

        methodB();   // self invocation
    }

    @Transactional
    public void methodB() {
        System.out.println("B");
    }
}

Spring sees @Transactional and creates a proxy around OrderService. Conceptually, imagine Spring generated something like this:

class OrderServiceProxy {

    private OrderService target;

    public void methodA() {
        target.methodA();
    }

    public void methodB() {

        transactionManager.begin();

        try {
            target.methodB();

            transactionManager.commit();
        } catch (Exception e) {
            transactionManager.rollback();
            throw e;
        }
    }
}


Now here inside methodA() we're calling this.methodB()
it doesn't go through the proxy
Transaction never sees it


To avoid this we need to move methodB() to another bean

@Service
public class OrderService {

    private final PaymentService paymentService;

    @Transactional
    public void methodA() {
        paymentService.methodB();
    }
}

@Service
public class PaymentService {

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void methodB() {
    }
}

What happens when a method annotated with @Transactional calls another method annotated with
@Async and the latter fails? Will the transaction roll back?
------------------------------------------------------------------------------------------------------

@Async tells Spring:
Don't execute this method on the caller's thread. Submit it to a TaskExecutor and execute it on another thread.
Spring's async support is enabled with @EnableAsync, and @Async is proxy-based

@Async executes the method on another thread through a TaskExecutor.
Spring's normal @Transactional context is thread-bound and does not propagate to the new async thread.
Therefore, the caller's transactional method usually returns and commits independently.
If the async method later throws an exception, that exception does not reach the original transactional proxy,
so the original transaction is not rolled back.

If the async operation needs database transactions,
it should have its own transaction. If the caller explicitly waits on a Future and propagates the failure before
its transaction commits, then the outer transaction can roll back.

ex :

@Service
public class EmailService {

    @Async
    public void sendEmail() {
        System.out.println(Thread.currentThread().getName());
        // send email
    }
}

@Service
public class OrderService {

    private final EmailService emailService;

    public void createOrder() {

        System.out.println("Before email");

        emailService.sendEmail();

        System.out.println("After email");
    }
}

Without Async order service has to wait until the email finishes

With Async the email execution will be done by another thread

Explain the difference between @RestController and @Controller in Spring Boot.
---------------------------------------------------------------------------------


@Controller is mainly used for Spring MVC applications that return views
@RestController is used for REST APIs that return data directly in the response body.

@RestController -> @Controller + @ResponseBody

@ResponseBody -> returns data directly in the response body.
