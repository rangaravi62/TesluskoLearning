Service Discovery
-------------------------------------
Service Discovery is a mechanism that enables microservices to locate and communicate with each other without
hardcoding IP addresses or ports.
services network locations change frequently.
A service registry like Eureka maintains the current locations of all services,
allowing clients to discover and communicate with them dynamically.

---------------------
Key Points
---------------------

Service registers with eureka server.
Eureka server maintains the registry.
Services sends the heartbeat to keep their registrations alive.
Consumers fetches the registry and call the required services.
If a service is down, eureka removes it from registry.


------------------------
Eureka Components
------------------------

Eureka Server -> Central server that maintains service registry
Service Provider -> Microservice that registers itself with Eureka
Service Consumer -> Microservice that discovers and call the other services
Eureka Client -> Library included in each microservices to interact with Eureka server



------------------------------------------------
Eureka
------------------------------------------------

Eureka is a service registry developed by netflix used for service discovery in microservices

We'll mainly be having

Eureka server -> maintains the service registry
Eureka client -> microservices that register themselves with eureka and discover other services

When a microservice starts, eureka client registers the service with eureka server using its
application name, host/ip, port and other instance metadata


Eureka clients periodically sends heartbeats to the eureka server
If any instance doesn't send the heartbeat with in the expiration period, Eureka considers it unavailable and can remove it from the registry.

Each instance caches information locally and periodically refreshes it.

--------------------------------------------------------------------------------------------------------------------------------
Q)We have 3 Payment Service instances registered with Eureka. One Payment instance suddenly crashes.
  What happens from the moment it crashes until Order Service stops sending traffic to that instance?
--------------------------------------------------------------------------------------------------------------------------------


If one payment service crashes then the eureka server stop recieving the heartbeat from that instance,
then eventually it removes the registry after the expiration period, and in the next refresh the order service
get the updated registries, and the load balancer(client side) will stop selecting the crashed instance.
meanwhile the requests which were sent to the crashed service result in connection errors or timeouts,
We can handle such failures using proper timeouts, retries, and circuit breakers.
